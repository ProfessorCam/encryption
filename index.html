Encryption and Protocols

HTTPS The same login page as the HTTP lab, now encrypted. And every key it used, handed to you.

Type a password and submit. It crosses the wire scrambled, so a plain Wireshark capture shows only ciphertext. But encryption is only as secret as its keys, and this page shows you all of them.

1. Log in over HTTPS

Start a Wireshark capture on your loopback interface first (filter: tls), then submit the form.

When you click Submit, the form data is sent inside TLS. Wireshark records it, but it stays scrambled until you load the keys below.

2. The keys HTTPS used

Two kinds of keys work together. The asymmetric keypair (left) is used to secretly agree on the symmetric key (right), and that symmetric key encrypts your data. Follow the arrow.

Classroom only. Showing a private key and turning off forward secrecy is deliberately insecure, the opposite of what a real server does.
Step 1 · Asymmetric

🔑 The keypair

Two matching keys. The public key (handed out in the certificate) locks; the private key unlocks. Your browser uses the public key to secretly pass the server a value that both sides turn into the symmetric key, so the asymmetric keypair is what safely sets up the symmetric one.

Step 2 · Symmetric

🔐 Session secrets

One fast key both sides share. It does the real work: everything you type, including your password, is encrypted with this. To read a capture in Wireshark, you load these secrets. Submit the form, then refresh this page to see your own session appear.

3. Decrypt it yourself in Wireshark

Capture on the loopback interface, filter with tls, submit the form, then decrypt:

  1. Session secrets (works everywhere, use this): download keylog.txt, then in Wireshark go to Preferences → Protocols → TLS → (Pre)-Master-Secret log filename and point it at the file.
  2. RSA private key (advanced, optional): Preferences → Protocols → TLS → RSA keys list → add server.key (IP any, port 443, protocol http). This only works because forward secrecy is off, and only on Wireshark builds whose crypto backend still supports raw RSA decryption. Many recent builds do not, so fall back to method 1.

Then right-click the decrypted packet → Follow → HTTP Stream and read your request: GET /action_page.php?name=Tux&pwd=...
